## 1. Обзор

**Mafia Coach** — локальный ассистент-тренер для игры в мафию в Telegram.
Программа подключается к Telegram как userbot (Telethon), в реальном времени читает
сообщения игрового чата, распознаёт фазы, события (убийства, голосования, раскрытия ролей
ботом) и через локальную LLM (LM Studio) выдаёт **вероятностную оценку ролей игроков**
и **объяснение рассуждений**.

Программа **не играет за пользователя** и **не отправляет сообщений в чат**.
Она — наблюдатель и тренер: помогает разбирать игру, копит статистику по игрокам
и дообучается на исторических партиях.

### Кратко о режиме работы

- **Один пользователь** (владелец ПК). Аутентификации/многопользовательского режима нет.
- **Только Windows**, только локально, запуск скриптом.
- **Два консольных окна** одновременно:
  1. **Stats Window** — таблица «игрок → наиболее вероятная роль + % уверенности», обновляется в реальном времени.
  2. **Reasoning Window** — поток рассуждений LLM по каждому новому событию (стриминг).
- **Только русский язык** во всём выводе и в промптах.

## 2. Цели и не-цели

### Цели (v1)
1. Автоматически подключаться к Telegram-чату через Telethon userbot.
2. Парсить сообщения в реальном времени и структурировать игру:
   регистрация, ночь/день, голосования, смерти, раскрытия ролей ботом.
3. Анализировать через LM Studio (REST API v1) и выдавать **JSON** с ролями и уверенностью.
4. Хранить историю партий и профили игроков в SQLite.
5. Автоматически размечать роли по сообщениям бота (кто кем оказался в итоге).
6. Копить данные для последующего **fine-tune** (LoRA) локальной модели.
7. Ведение подробных логов анализа (для ретроспективы и отладки).

### Не-цели (не сейчас)
- Не играет автономно, не пишет в чат, не голосует.
- Не поддерживает голосовой чат (игра всегда текстовая).
- Нет веб-интерфейса, нет GUI, нет API-сервера.
- Нет многопользовательского режима.
- Нет шифрования/защиты персональных данных (по решению владельца).
- Не поддерживает несколько языков, только русский.

## 3. Пользователь и сценарий использования

- **Кто:** один человек (владелец). Используется как **тренер** — чтобы улучшать
  собственную игру и разбирать партии других.
- **Сценарий:**
  1. Пользователь запускает `python main.py`.
  2. Открываются два консольных окна.
  3. Программа подключается к аккаунту Telegram (сессия уже авторизована заранее).
  4. Подключается к активному игровому чату из конфига (или ждёт команды `/attach <chat>` в основном окне запуска оркестратора; дочерние окна служат только для отображения).
  5. По мере событий таблица в Stats Window обновляется через IPC, Reasoning Window показывает
     поток мыслей модели.
  6. По завершении партии данные сохраняются в SQLite и доступны для ретроспективы
     и будущего fine-tune.

## 4. Домен: правила мафии

Источник: официальные правила мафии (файл `rules/Mafia_rules.txt`).

### 4.1 Роли

**Мирные (10):**
`Комиссар Каттани`, `Сержант`, `Доктор`, `Любовница`, `Бомж`, `Мирный житель`,
`Счастливчик`, `Камикадзе`, `Самоубийца`, `Мэр`.

**Мафия (5):**
`Дон`, `Мафия`, `Адвокат`, `Убийца`, `Журналист`.

**Нейтральные (6):**
`Маньяк`, `Поджигатель`, `Аферист`, `Стукач`, `Маг`, `Оборотень`.

Каждая роль в конфиге `configs/roles.yaml` описана полями:
`id`, `name_ru`, `faction` (`town|mafia|neutral`), `category` (активная/пассивная),
`night_actions` (список), `can_kill`, `can_check`, `can_heal`, `notes`,
`bot_aliases` (как эту роль называет бот в сообщениях, для авторазметки).

### 4.2 Мета-правила клуба (влияют на эвристики тренера)

- Первые **2 игровых дня** линч без аргументов запрещён (кроме линча нарушителя
  и партий на 29+ игроков). Значит ИИ не должен подталкивать к «рандому».
- **В первую ночь** запрещены действия против игрока с АнтиТаргетом для ролей:
  Любовница, Комиссар Каттани, Дон, Маньяк, Убийца (искл. если живых ≤8).
- Запрет на «порчу игры»: например, Комиссар не должен стрелять без проверки,
  Доктор не должен лечить открытую мафию и т.п. Это **признаки** того, что игрок
  играет неоптимально — их учитываем в эвристиках, но НЕ советуем нарушать правила.

Правила из `rules/Mafia_rules.txt` используются:
- как справочник при генерации эвристик;
- как база для валидации действий ролей (что допустимо, что нет).

## 5. Источники данных и поток

```
Telegram (Telethon userbot)
        │
        ▼  новые сообщения (raw)
   parser/                 классификация сообщений:
        │                  - игровое событие
        │                  - системное сообщение бота (роль, смерть, фаза)
        │                  - речь игрока
        │                  - нерелевантное
        ▼
   domain/ (GameState)     наполнение событий:
        │                  - фазы (night/day/vote/registration/end)
        │                  - участники, живые/мёртвые
        │                  - известные роли (из сообщений бота)
        ▼
   analyzer/               формирование запроса к LLM:
        │                  - контекст партии
        │                  - история речи игроков
        │                  - профили игроков из памяти
        │                  - правила и предыдущие предсказания
        ▼
   llm/ (LM Studio)        REST /v1/chat/completions
        │                  structured output: JSON с ролями и уверенностью
        │                  + стриминг reasoning в Reasoning Window
        ▼
   memory/ (SQLite)        сохранение событий, предсказаний, финальных ролей
        │
        ▼
   ui/ (два окна)          Stats Window: таблица
                           Reasoning Window: поток мыслей
```

**Не отправляем ничего в Telegram. Только чтение.**

## 7. Модель данных (SQLite)

Схема v1 (детали уточняются при реализации; см. `infra/db/migrations/`).

```sql
-- Игроки (глобально, сквозь все партии)
CREATE TABLE players (
    id              INTEGER PRIMARY KEY,      -- Telegram user id
    username        TEXT,                     -- текущий username
    first_seen_at   TIMESTAMP,
    last_seen_at    TIMESTAMP,
    notes           TEXT                      -- ручные/авто метки: "блефует", "агрессивный"…
);

-- Партии
CREATE TABLE games (
    id              INTEGER PRIMARY KEY,
    chat_id         INTEGER,
    started_at      TIMESTAMP,
    ended_at        TIMESTAMP,
    player_count    INTEGER,
    winner_faction  TEXT                       -- town|mafia|neutral|mixed|unknown|NULL
                                               -- NULL: END_GAME не было (закрытая партия заброшена)
                                               -- mixed: победители из нескольких фракций
                                               -- unknown: роль не распознана или нет победителей
);

-- Участие игрока в партии
CREATE TABLE game_players (
    id              INTEGER PRIMARY KEY,
    game_id         INTEGER REFERENCES games(id),
    player_id       INTEGER REFERENCES players(id),
    final_role      TEXT,                      -- из сообщения бота
    survived        INTEGER                    -- 0/1
);

-- События (единый поток)
CREATE TABLE events (
    id              INTEGER PRIMARY KEY,
    game_id         INTEGER REFERENCES games(id),
    ts              TIMESTAMP,
    kind            TEXT,                      -- message|death|vote|role_reveal|phase_change
    actor_id        INTEGER,                   -- если применимо
    target_id       INTEGER,                   -- если применимо
    phase           TEXT,
    day_number      INTEGER,
    payload_json    TEXT                       -- текст, метаданные
);

-- Предсказания ИИ
CREATE TABLE predictions (
    id              INTEGER PRIMARY KEY,
    game_id         INTEGER REFERENCES games(id),
    ts              TIMESTAMP,
    player_id       INTEGER REFERENCES players(id),
    predicted_role  TEXT,
    confidence      REAL,                      -- 0..1
    reasoning       TEXT,                      -- модель reasoning (для ретроспективы)
    correct         INTEGER                    -- 0/1/null — заполняется в конце партии
);

-- Профиль стиля речи
CREATE TABLE player_style (
    player_id       INTEGER REFERENCES players(id),
    tag             TEXT,                      -- "частые отмазки", "пассив"
    weight          REAL,                      -- уверенность/частота
    evidence_json   TEXT,
    PRIMARY KEY (player_id, tag)
);
```

## 8. LLM / LM Studio

- **Модель:** `qwen/qwen3.5-9b` (идентификатор должен совпадать с именем загруженной
  модели в LM Studio и с ответом `GET /v1/models`).
- **Endpoint:** `http://localhost:1234/v1/chat/completions` (OpenAI-совместимый).
- **Режим:** structured output (JSON Schema через `response_format`), стриминг для
  окна рассуждений.
- **Язык:** только русский, в промптах требовать «отвечай по-русски, JSON — только по схеме».
- **Температура:** ~0.2–0.4 (аналитика), для reasoning допускается выше.
- **Ограничения по железу:** оставляем запас по контексту (не грузить всю историю
  партии целиком — только скользящее окно + суммаризация).

**Схема ответа модели (v1):**

```json
{
  "analysis": [
    {
      "player_id": 123,
      "player_name": "Вася",
      "suspected_role": "Мафия",
      "confidence": 0.65,
      "alternative": { "role": "Мирный житель", "confidence": 0.25 },
      "reasons": ["уклончивые ответы", "голосовал против комиссара"]
    }
  ],
  "game_read": "краткое описание текущей картины партии",
  "reasoning": "пошаговые рассуждения"
}
```

`reasoning` в ответе может отсутствовать, быть `null` или пустой строкой.
В `predictions.reasoning` сохраняется полный `AnalysisResponse.reasoning`; если
он отсутствует или пуст, сохраняются `reasons` конкретного игрока, соединённые
переводами строк. Причины по каждому игроку отдельно сохраняются в
`predictions_history.reasoning` как строки, соединённые переводами строк.

## 9. Обучение и память

### 9.1 Онлайн (в рамках партии)
- Скользящее окно событий + профили игроков из БД.
- Предсказания обновляются при каждом новом значимом событии.

### 9.2 Автоматическая разметка
- Парсер вычленяет из сообщений бота объявления ролей («X был Мафией»,
  «Проверка Комиссара: Y — Мирный» и т.п.) — это **ground truth** для дообучения.
- По завершении партии `predictions.correct` заполняется сравнением с `final_role`.

### 9.3 Ретроспектива (после партии)
- Сохраняется полный лог: события + предсказания + `reasoning` + итоговые роли.
- Используется для:
  - анализа ошибок модели (какие паттерны она пропустила);
  - построения датасета для fine-tune.

### 9.4 Fine-tune (постфактум)
- **Не в рамках v1.** Отдельный оффлайн-пайплайн (LoRA, Unsloth/Axolotl).
- Формат датасета — ChatML/SFT: `messages` с системным промптом (правила + роль)
  и `assistant` ответом (JSON предсказаний). `reasoning` используется отдельным каналом.
- Цель: дообучить модель на стиле и паттернах, характерных для этого клуба.

## 10. Telegram (Telethon userbot)

- **Только чтение** сообщений в игровом чате.
- Сессия уже авторизована вручную пользователем (`*.session` файл в `data/sessions/`).
- Подключение к чату по `chat_id` (можно указать в конфиге или выбрать командой `/attach` в основном окне запуска оркестратора, см. §15.9).
- Парсинг: `message.text`, `message.from_user`, `message.reply_to_message`, время.
- Игнорируем: сообщения не из игрового чата, сообщения самого userbot’а, стикеры/медиа
  (кроме текста в подписи, если нужно).
- **Никаких исходящих сообщений.**

## 11. Конфигурация

Файлы в `configs/`:

- `settings.yaml` — ключи Telegram (`session_file`, `api_id`, `api_hash`), селектор игрового чата (`chat_id`), селектор игрового бота (`bot_username` или `bot_id`), адрес LM Studio (`base_url`, `model`), настройки триггера LLM (`trigger_mode`), пути к SQLite БД (`db.path`), лимиты контекста, логирование.
- `roles.yaml` — полный список ролей с описанием и алиасами бота.

Шаблоны промптов вынесены в `infra/llm/prompts/` (`system.jinja`, `analyze.jinja`).
Состав ролей из сообщения бота «Живые игроки … Из них … Всего: N» — точные
входные данные для LLM: промпт показывает канонические названия ролей, число
слотов, число разных ролей, список живых и требует распределить все слоты по
всем живым игрокам (включая синтетические ID для молчавших игроков). Прошлые
предсказания передаются якорем: смена роли без нового аргумента не принимается.
`trigger_mode` по умолчанию — `batch_debounce` (в `queue` анализ после одного
сообщения бота не запускается). JSON-схема ответа `AnalysisResponse` не меняется.
